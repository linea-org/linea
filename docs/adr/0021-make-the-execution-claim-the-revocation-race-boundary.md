# Make the Execution Claim the Revocation Race Boundary

The Connector Gateway may execute an Action Intent only after atomically claiming it from `ready` to `executing` while its Connection remains active and its approving Decision remains valid. Connection revocation, External Subject disablement, or execution cancellation wins by committing before that claim and atomically cancels every affected non-executing intent and pending Approval Request; after the claim, the intent must report `succeeded`, `failed`, `stale`, or `outcome_unknown` rather than falsely claiming cancellation. Provider revocation uses a one-purpose encrypted outbox payload that normal connector execution cannot resolve, allowing local authority to end immediately while provider-side cleanup remains best-effort and recoverable.

The worker's claim of a queued or resumed Execution is the same boundary for non-Connector work: it share-locks the Execution's External Subject, Environment, Workflow or Agent and, for deployment starts, its Environment binding, and fails the Execution with `authority_revoked` if the subject is disabled or erased, the Environment disabled, the definition archived or the binding disabled. Every resume (Approval Decision, wait timer, finished nested Agent) re-queues through that claim, so a revocation committed before it stops the Execution there; an Execution already claimed keeps its lease until its next claim. Environment key revocation is deliberately not an input, because an Execution records no key and the Environment owns its authority. An Execution with an `executing` Action Intent is still claimed so the Connector Gateway can recheck authority and report that intent's outcome.
