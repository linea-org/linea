# Resolve step references once and record what they read

A step's input is the output of the step before it, which left no way to put a value in a prompt, a URL or a header. Some config fields may now hold references: `{{steps.<id>.<path>}}` for any earlier step, `{{input.<path>}}` for the step's own input, `{{variables.<name>}}` and `{{secrets.<NAME>}}`. In a request body or a variable, text that is only a reference keeps the value's type; anywhere else the value becomes text. Each field declares whether it takes references, so other text keeps its braces. `\{{` writes literal braces. A system prompt takes none, because it would carry a value from outside into the model's trusted instructions.

References are found and replaced in one pass over the config as written. Replacing in two passes, secrets last, would let a value from a model or an API contain `{{secrets.KEY}}` and have it filled in. Secrets may be used only in an HTTP step's headers and body, never model provider keys, only over HTTPS, and only when the URL's origin is written out, so no value can choose where a secret goes. Inky does not test-run a draft that sends one, because a page it read could have chosen the address. In a URL every value after the first position is percent-encoded, and a value that would empty or move a path segment fails the step.

A reference must name a step that always runs before its own, checked when a graph is saved as a version or test-run; published graphs are not checked again. A path that has no value fails the step, instead of sending an empty string.

The values read, but never secrets, are stored with the step. The step ran on them as well as on its input, so the trace, a Replay and a Regression Case need them, and they are redacted, hidden from members and erased with its input. A Replay reads them from there, and from the source run's checkpoint when a changed prompt names a step it did not use before. A Regression Case keeps its own copy and reports an error for a reference it does not have.
