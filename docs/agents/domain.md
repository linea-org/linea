# Domain documentation

Use a single-context layout: root `GLOSSARY.md` and `docs/adr/`.

Before exploring domain behavior, read `GLOSSARY.md` and the ADRs relevant
to the work. Use the glossary's canonical terms in code, specs, and tickets.
If a referenced document is absent, continue with available sources.

Surface conflicts with existing ADRs explicitly before changing behavior.
Record new terms and decisions through the domain-modeling workflow.
